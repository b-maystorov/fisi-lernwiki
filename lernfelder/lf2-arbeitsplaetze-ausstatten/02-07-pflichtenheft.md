# 2.7 Pflichtenheft erstellen

In diesem Kapitel geht es darum, Anforderungen aus einer Analyse in ein konkretes Pflichtenheft zu übertragen.

Ein Pflichtenheft beschreibt, wie eine IT-Lösung umgesetzt werden soll. Es ist damit ein wichtiges Dokument zwischen Planung, Angebot, Umsetzung, Test und Übergabe.

Für Fachinformatiker für Systemintegration ist das Pflichtenheft wichtig, weil technische Lösungen nachvollziehbar geplant und später überprüfbar umgesetzt werden müssen.

---

## Kurz erklärt

Ein Pflichtenheft beschreibt die konkrete Umsetzung einer Lösung.

Es beantwortet die Frage:

> Wie wird die geforderte Lösung technisch umgesetzt?

Dabei werden Anforderungen aus Kundengespräch, Bedarfsanalyse oder Lastenheft in konkrete technische Maßnahmen übersetzt.

Ein Pflichtenheft kann zum Beispiel beschreiben:

- welche Hardware eingesetzt wird
- welche Software installiert wird
- welche Benutzerrechte eingerichtet werden
- wie Netzwerkzugang umgesetzt wird
- welche Sicherheitsmaßnahmen gelten
- welche Tests durchgeführt werden
- wann die Lösung als erfolgreich gilt

---

## Lastenheft und Pflichtenheft

Lastenheft und Pflichtenheft werden oft verwechselt, haben aber unterschiedliche Aufgaben.

| Dokument      | Erstellt durch                   | Inhalt                        | Leitfrage              |
| ------------- | -------------------------------- | ----------------------------- | ---------------------- |
| Lastenheft    | Auftraggeber / Kunde             | Anforderungen, Wünsche, Ziele | Was wird benötigt?     |
| Pflichtenheft | Auftragnehmer / IT-Dienstleister | konkrete technische Umsetzung | Wie wird es umgesetzt? |

Das Lastenheft beschreibt also eher die Sicht des Kunden.  
Das Pflichtenheft beschreibt die technische Lösung aus Sicht des IT-Dienstleisters.

---

## Zweck eines Pflichtenhefts

Ein Pflichtenheft sorgt dafür, dass alle Beteiligten das gleiche Verständnis von der geplanten Lösung haben.

Es hilft bei:

- Planung
- Angebotserstellung
- Beschaffung
- Umsetzung
- Projektsteuerung
- Tests
- Abnahme
- Dokumentation
- späterer Wartung

Ohne Pflichtenheft können Missverständnisse entstehen, weil nicht klar ist, was genau geliefert, eingerichtet oder getestet werden soll.

---

## Inhalt eines Pflichtenhefts

Ein Pflichtenheft sollte klar, strukturiert und prüfbar sein.

Typische Inhalte sind:

| Bereich            | Inhalt                                          |
| ------------------ | ----------------------------------------------- |
| Ausgangssituation  | aktuelle Umgebung und Problemstellung           |
| Ziel der Lösung    | gewünschter Zustand nach Umsetzung              |
| Leistungsumfang    | was umgesetzt wird                              |
| Abgrenzung         | was nicht Teil des Auftrags ist                 |
| technische Lösung  | Hardware, Software, Netzwerk, Sicherheit        |
| Anforderungen      | funktionale und nicht-funktionale Anforderungen |
| Systemumgebung     | vorhandene Infrastruktur                        |
| Umsetzungsschritte | geplantes Vorgehen                              |
| Tests              | Prüfungen vor Übergabe                          |
| Akzeptanzkriterien | Bedingungen für erfolgreiche Abnahme            |
| Dokumentation      | technische und organisatorische Dokumente       |
| Zeitplan           | grobe Termine und Meilensteine                  |
| Risiken            | mögliche Probleme und Einschränkungen           |

Ein gutes Pflichtenheft ist nicht unnötig kompliziert, aber vollständig genug, damit die Umsetzung nachvollziehbar ist.

---

## Anforderungen im Pflichtenheft

Anforderungen müssen im Pflichtenheft möglichst eindeutig beschrieben werden.

Schlecht wäre:

> Der Arbeitsplatz soll schnell sein.

Besser wäre:

> Der Arbeitsplatz wird mit 16 GB RAM, NVMe-SSD und Business-Laptop ausgestattet, damit Office, Browser, Videokonferenzsoftware und Fachanwendung parallel flüssig genutzt werden können.

Eine gute Anforderung sollte:

- eindeutig sein
- prüfbar sein
- realistisch sein
- technisch umsetzbar sein
- zum Kundenbedarf passen
- dokumentiert sein

Unklare Anforderungen erschweren Umsetzung und Abnahme.

---

## Funktionale Anforderungen im Pflichtenheft

Funktionale Anforderungen beschreiben konkrete Funktionen.

Beispiele:

- Benutzer kann sich mit seinem Firmenkonto anmelden.
- Zugriff auf Netzlaufwerk der Abteilung ist eingerichtet.
- Netzwerkdrucker ist installiert.
- Office-Programme sind nutzbar.
- Fachsoftware ist installiert und startet fehlerfrei.
- Laptop kann über Dockingstation zwei Monitore verwenden.
- WLAN und LAN funktionieren.
- Benutzerprofil wird korrekt geladen.

Funktionale Anforderungen lassen sich meistens direkt testen.

---

## Nicht-funktionale Anforderungen im Pflichtenheft

Nicht-funktionale Anforderungen beschreiben Qualitätsmerkmale.

Dazu gehören:

| Bereich          | Bedeutung                                  |
| ---------------- | ------------------------------------------ |
| Leistung         | System arbeitet ausreichend schnell        |
| Verfügbarkeit    | System ist zuverlässig nutzbar             |
| Sicherheit       | Daten und Zugänge sind geschützt           |
| Bedienbarkeit    | Benutzer kann sinnvoll damit arbeiten      |
| Wartbarkeit      | IT kann System später pflegen              |
| Kompatibilität   | Lösung passt zur vorhandenen Infrastruktur |
| Skalierbarkeit   | Lösung kann später erweitert werden        |
| Energieeffizienz | angemessener Stromverbrauch                |

Diese Anforderungen sind wichtig, weil ein System nicht nur funktionieren, sondern langfristig gut betrieben werden muss.

---

## Technische Beschreibung der Lösung

Im Pflichtenheft wird beschrieben, welche technische Lösung umgesetzt wird.

Bei einem Arbeitsplatzprojekt kann dazu gehören:

- Gerätetyp
- CPU
- RAM
- SSD
- Monitoranzahl
- Dockingstation
- Betriebssystem
- Softwarepakete
- Benutzerkonto
- Netzwerkzugang
- Drucker
- Sicherheitssoftware
- Verschlüsselung
- Backup-Anbindung
- Verwaltungssoftware
- Supportmodell

Je genauer diese Punkte beschrieben werden, desto leichter ist später die Umsetzung und Kontrolle.

---

## Pflichtenheft für Desktop-PCs und Workstations

Desktop-PCs und Workstations sind feste Arbeitsplatzsysteme.

Sie eignen sich besonders, wenn Mobilität nicht wichtig ist, aber Leistung, Erweiterbarkeit oder stabile Arbeitsumgebung benötigt werden.

Wichtige Punkte im Pflichtenheft:

| Bereich        | Inhalt                                            |
| -------------- | ------------------------------------------------- |
| CPU            | benötigte Leistung, Kerne, Virtualisierung        |
| RAM            | Größe, Erweiterbarkeit, eventuell ECC             |
| Speicher       | SSD-Größe, Geschwindigkeit, zusätzliche Laufwerke |
| Grafik         | integrierte oder dedizierte GPU                   |
| Anschlüsse     | USB, DisplayPort, HDMI, LAN                       |
| Monitore       | Anzahl, Größe, Auflösung                          |
| Netzwerk       | LAN, eventuell WLAN                               |
| Gehäuse        | Formfaktor, Wartbarkeit, Platz                    |
| Netzteil       | Leistung und Effizienz                            |
| Betriebssystem | Version und Lizenz                                |
| Software       | Standardsoftware und Fachanwendungen              |
| Sicherheit     | Verschlüsselung, TPM, BIOS/UEFI-Schutz            |

Workstations werden oft für leistungsintensive Aufgaben genutzt, zum Beispiel CAD, Simulation, Entwicklung, Datenanalyse oder Medienbearbeitung.

---

## Pflichtenheft für Laptops

Laptops sind mobile Arbeitsplatzsysteme.

Sie eignen sich für Büro, Homeoffice, Außendienst und hybrides Arbeiten.

Wichtige Punkte im Pflichtenheft:

| Bereich           | Inhalt                             |
| ----------------- | ---------------------------------- |
| Mobilität         | Gewicht, Größe, Akkulaufzeit       |
| Leistung          | CPU, RAM, SSD passend zur Aufgabe  |
| Display           | Größe, Auflösung, Helligkeit       |
| Docking           | USB-C, Thunderbolt, Dockingstation |
| Netzwerk          | WLAN, LAN über Adapter oder Dock   |
| Sicherheit        | TPM, Secure Boot, Verschlüsselung  |
| Kamera / Mikrofon | wichtig für Videokonferenzen       |
| Tastatur          | Layout, Beleuchtung, Ergonomie     |
| Garantie          | Business-Support, Vor-Ort-Service  |
| Verwaltung        | zentrale Geräteverwaltung möglich  |

Bei Laptops ist Sicherheit besonders wichtig, weil sie leichter verloren gehen oder gestohlen werden können.

---

## Pflichtenheft für Tablets

Tablets sind mobile Geräte mit Touch-Bedienung.

Sie eignen sich für einfache mobile Aufgaben, Präsentationen, Außendienst, Lager, Service oder digitale Formulare.

Wichtige Punkte:

- Displaygröße
- Akkulaufzeit
- Betriebssystem
- App-Kompatibilität
- Touch- oder Stifteingabe
- WLAN oder Mobilfunk
- Geräteschutz
- zentrale Verwaltung
- Sicherheitsrichtlinien
- Zugriff auf Unternehmensdaten
- Datenschutz
- Support und Reparatur

Tablets sind oft weniger flexibel als klassische Laptops, können aber für bestimmte Arbeitsprozesse sehr praktisch sein.

---

## Pflichtenheft für Thin Clients

Ein Thin Client ist ein einfacher Arbeitsplatzrechner, bei dem viele Aufgaben nicht lokal, sondern zentral auf Servern oder in einer virtuellen Umgebung laufen.

Der Thin Client dient vor allem als Zugriffspunkt auf zentrale Anwendungen oder Desktops.

Wichtige Punkte:

| Bereich           | Inhalt                                 |
| ----------------- | -------------------------------------- |
| Netzwerk          | stabile und schnelle Verbindung        |
| Serverumgebung    | zentrale Systeme müssen verfügbar sein |
| Benutzeranmeldung | Zugriff auf zentrale Umgebung          |
| Peripherie        | Monitor, Tastatur, Maus, Drucker       |
| Sicherheit        | wenig lokale Daten, zentrale Kontrolle |
| Wartung           | einfache Verwaltung vieler Geräte      |
| Leistung          | lokal oft geringere Anforderungen      |
| Ausfallsicherheit | abhängig von Netzwerk und Servern      |

Thin Clients sind besonders interessant, wenn Arbeitsplätze zentral verwaltet werden sollen.

Der Nachteil ist: Wenn Netzwerk oder zentrale Server ausfallen, kann der Arbeitsplatz oft nicht sinnvoll genutzt werden.

---

## Desktop as a Service

Desktop as a Service, kurz DaaS, bedeutet, dass der Arbeitsplatz als virtueller Desktop aus der Cloud oder einem Rechenzentrum bereitgestellt wird.

Der Benutzer arbeitet dann nicht hauptsächlich auf einem lokalen PC, sondern verbindet sich mit einer zentral bereitgestellten Desktop-Umgebung.

Wichtige Merkmale:

- Desktop läuft zentral
- Zugriff über Internet oder Firmennetz
- lokale Hardware kann einfacher sein
- Daten liegen zentral
- Verwaltung erfolgt zentral
- monatliche Kosten möglich
- starke Abhängigkeit von Netzwerk und Anbieter

DaaS kann sinnvoll sein für mobile Arbeit, externe Mitarbeiter, standardisierte Arbeitsplätze oder schnell skalierbare Umgebungen.

Wichtige Punkte im Pflichtenheft:

- benötigte Benutzeranzahl
- Leistung der virtuellen Desktops
- Speicherbedarf
- Zugriffsschutz
- Mehrfaktor-Authentifizierung
- Datenschutz
- Netzwerkbandbreite
- Verfügbarkeit
- Backup
- Support
- Kostenmodell

---

## Kauf, Miete, Leasing und Finanzierung

IT-Arbeitsplätze können auf verschiedene Arten beschafft werden.

| Modell       | Erklärung                                              |
| ------------ | ------------------------------------------------------ |
| Kauf         | Gerät wird direkt gekauft und gehört dem Unternehmen   |
| Miete        | Gerät wird für eine bestimmte Zeit gemietet            |
| Leasing      | Gerät wird über Laufzeit genutzt, oft mit festen Raten |
| Finanzierung | Kaufpreis wird über Raten bezahlt                      |
| DaaS         | Arbeitsplatz wird als Dienstleistung bereitgestellt    |

Die Wahl des Modells beeinflusst Kosten, Flexibilität, Eigentum, Wartung und Austauschzyklen.

---

## Kauf

Beim Kauf wird das Gerät direkt bezahlt und gehört dem Unternehmen.

Vorteile:

- Eigentum liegt beim Unternehmen
- keine laufenden Mietraten
- freie Nutzung
- langfristig oft günstiger bei langer Nutzung

Nachteile:

- hohe Anfangskosten
- Unternehmen trägt Risiko für Alterung
- Austausch muss selbst geplant werden
- Wartung und Entsorgung müssen organisiert werden

Kauf ist sinnvoll, wenn Geräte lange genutzt werden sollen und das Unternehmen selbst die Kontrolle behalten möchte.

---

## Miete

Bei Miete wird Hardware für eine bestimmte Zeit genutzt, ohne sie zu besitzen.

Vorteile:

- geringere Anfangskosten
- flexible Laufzeiten möglich
- Austausch oft einfacher
- Wartung kann enthalten sein

Nachteile:

- Gerät gehört nicht dem Unternehmen
- langfristig eventuell teurer
- Vertragsbedingungen beachten
- Abhängigkeit vom Anbieter

Miete kann sinnvoll sein bei kurzfristigen Projekten, Schulungen oder temporären Arbeitsplätzen.

---

## Leasing

Leasing ist eine langfristige Nutzungsform mit regelmäßigen Raten.

Vorteile:

- planbare monatliche Kosten
- regelmäßiger Austausch möglich
- Liquidität wird geschont
- Service kann enthalten sein

Nachteile:

- Vertragsbindung
- Gesamtkosten können höher sein
- Rückgabebedingungen beachten
- Änderungen während der Laufzeit können schwierig sein

Leasing wird häufig eingesetzt, wenn Unternehmen regelmäßig moderne Hardware nutzen möchten.

---

## Finanzierung

Bei Finanzierung wird ein Gerät gekauft, aber über Raten bezahlt.

Vorteile:

- Gerät kann direkt genutzt werden
- Eigentum kann beim Unternehmen liegen
- Kosten werden verteilt

Nachteile:

- Zinsen oder Zusatzkosten möglich
- finanzielle Verpflichtung über längere Zeit
- Gerät kann während der Zahlung technisch veralten

Finanzierung ist eher eine wirtschaftliche Entscheidung und muss zur Finanzplanung des Unternehmens passen.

---

## Vergleich der Beschaffungsmodelle

| Modell       | Vorteil                                 | Nachteil                           |
| ------------ | --------------------------------------- | ---------------------------------- |
| Kauf         | volle Kontrolle, Eigentum               | hohe Anfangskosten                 |
| Miete        | flexibel, gut für kurze Nutzung         | langfristig eventuell teuer        |
| Leasing      | planbare Kosten, regelmäßiger Austausch | Vertragsbindung                    |
| Finanzierung | Kosten werden verteilt                  | Zinsen und Verpflichtungen         |
| DaaS         | zentral, skalierbar, flexibel           | abhängig von Netzwerk und Anbieter |

Im Pflichtenheft sollte erkennbar sein, welches Modell genutzt wird und warum es zur Situation passt.

---

## Akzeptanzkriterien im Pflichtenheft

Akzeptanzkriterien legen fest, wann die Lösung als erfolgreich umgesetzt gilt.

Sie sind wichtig für Test und Abnahme.

Beispiele:

- Gerät startet ohne Fehler.
- Betriebssystem ist installiert und aktiviert.
- Benutzer kann sich anmelden.
- benötigte Software ist installiert.
- Netzwerkzugang funktioniert.
- Drucker ist eingerichtet.
- Sicherheitssoftware ist aktiv.
- Festplattenverschlüsselung ist aktiviert.
- Updates sind installiert.
- Dokumentation wurde übergeben.

Akzeptanzkriterien müssen prüfbar sein. Nur dann kann objektiv entschieden werden, ob die Leistung erfüllt wurde.

---

## Abgrenzung im Pflichtenheft

Ein Pflichtenheft sollte auch beschreiben, was nicht Teil des Auftrags ist.

Das nennt man Abgrenzung.

Beispiele:

- keine Migration alter lokaler Daten
- keine Schulung über Standardsoftware hinaus
- keine Einrichtung privater Geräte
- keine Betreuung außerhalb der vereinbarten Zeiten
- keine Anpassung der Fachsoftware
- keine Netzwerkverkabelung, wenn nur Arbeitsplatzinstallation beauftragt wurde

Abgrenzung ist wichtig, damit später keine falschen Erwartungen entstehen.

---

## Änderungen am Pflichtenheft

Anforderungen können sich während eines Projekts ändern.

Änderungen sollten dokumentiert und freigegeben werden.

Wichtig ist:

- Was soll geändert werden?
- Warum ist die Änderung notwendig?
- Welche Auswirkungen hat sie auf Kosten?
- Welche Auswirkungen hat sie auf Zeit?
- Welche Auswirkungen hat sie auf Sicherheit?
- Wer hat die Änderung freigegeben?

Ohne kontrollierte Änderungen kann ein Projekt schnell unübersichtlich werden.

---

## Qualität eines guten Pflichtenhefts

Ein gutes Pflichtenheft ist:

- verständlich
- strukturiert
- vollständig
- realistisch
- prüfbar
- technisch korrekt
- wirtschaftlich nachvollziehbar
- mit dem Kunden abgestimmt
- versionskontrolliert

Es sollte nicht nur für Techniker verständlich sein, sondern auch für Kunden, Entscheider und Support.

---

## Praxisbeispiele

### Beispiel 1: Büroarbeitsplatz

Ein Pflichtenheft für einen Büroarbeitsplatz beschreibt Gerätetyp, Betriebssystem, Standardsoftware, Benutzerkonto, Netzwerkzugang, Drucker, Verschlüsselung, Updates und Übergabekriterien.

### Beispiel 2: Laptop für Homeoffice

Ein Pflichtenheft für Homeoffice beschreibt Laptop, Dockingstation, VPN oder Cloud-Zugriff, Webcam, Headset, Festplattenverschlüsselung, Mehrfaktor-Authentifizierung und Supportweg.

### Beispiel 3: Thin-Client-Arbeitsplatz

Ein Pflichtenheft für Thin Clients beschreibt zentrale Desktopumgebung, Serverabhängigkeit, Netzwerkqualität, Benutzeranmeldung, Peripherie, Sicherheitsrichtlinien und Ausfallszenarien.

---

## Typische Fehler

| Fehler                                   | Problem                                                 |
| ---------------------------------------- | ------------------------------------------------------- |
| Pflichtenheft zu ungenau                 | Umsetzung und Abnahme werden schwierig                  |
| Lastenheft und Pflichtenheft verwechseln | Kundenwunsch und technische Lösung werden vermischt     |
| Anforderungen nicht prüfbar formulieren  | Tests sind nicht eindeutig                              |
| Abgrenzung fehlt                         | Kunde erwartet mehr als vereinbart                      |
| Sicherheitsanforderungen fehlen          | späterer Nachbesserungsaufwand                          |
| Änderungen nicht dokumentieren           | Projekt verliert Kontrolle                              |
| Betrieb und Support nicht beachten       | Lösung funktioniert nur bei Übergabe, nicht langfristig |
| keine Akzeptanzkriterien                 | Abnahme wird subjektiv                                  |

---

## FISI-Bezug

Für Fachinformatiker für Systemintegration ist das Pflichtenheft ein wichtiges Planungs- und Arbeitsdokument.

Es verbindet Kundenanforderungen mit technischer Umsetzung.

Ein FISI muss aus Anforderungen konkrete technische Lösungen ableiten können. Dazu gehören Hardware, Software, Netzwerk, Sicherheit, Betrieb, Support und Dokumentation.

Ein gutes Pflichtenheft hilft dabei, sauber zu arbeiten, Missverständnisse zu vermeiden und die spätere Lösung objektiv zu prüfen.

---

## Kurze Zusammenfassung

Ein Pflichtenheft beschreibt, wie eine IT-Lösung umgesetzt wird.

Es entsteht auf Grundlage von Kundenanforderungen, Bedarfsanalyse oder Lastenheft.

Wichtige Inhalte sind Ziel, Leistungsumfang, technische Lösung, Anforderungen, Abgrenzung, Tests, Akzeptanzkriterien, Dokumentation, Zeitplan und Risiken.

Für IT-Arbeitsplätze kann das Pflichtenheft unterschiedliche Gerätetypen und Beschaffungsmodelle beschreiben, zum Beispiel Desktop-PC, Workstation, Laptop, Tablet, Thin Client, Desktop as a Service, Kauf, Miete oder Leasing.

Für FISI ist das Pflichtenheft wichtig, weil es technische Planung, Umsetzung, Test und Übergabe nachvollziehbar macht.

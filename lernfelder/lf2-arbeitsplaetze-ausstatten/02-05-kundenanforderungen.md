# 2.5 Kundenanforderungen im Leistungsprozess berücksichtigen

In diesem Kapitel geht es darum, Kundenanforderungen zu erkennen, zu verstehen, zu dokumentieren und im gesamten Leistungsprozess zu berücksichtigen.

Ein IT-Arbeitsplatz wird nicht einfach nach Gefühl zusammengestellt. Die Ausstattung muss zu den Aufgaben, Arbeitsabläufen, Sicherheitsanforderungen, dem Budget und den Erwartungen des Kunden passen.

Für Fachinformatiker für Systemintegration ist dieses Thema wichtig, weil technische Lösungen nur dann gut sind, wenn sie zum tatsächlichen Bedarf passen.

---

## Kurz erklärt

Kundenanforderungen beschreiben, was ein Kunde von einer IT-Lösung erwartet oder benötigt.

Dabei geht es nicht nur um technische Daten wie CPU, RAM oder Speicherplatz. Es geht auch um Arbeitsprozesse, Benutzerfreundlichkeit, Sicherheit, Kosten, Support, Datenschutz und spätere Wartung.

Eine gute IT-Lösung entsteht nicht dadurch, dass man das stärkste Gerät auswählt, sondern dadurch, dass man die Anforderungen sauber versteht und daraus eine passende Lösung ableitet.

---

## Was bedeutet Leistungsprozess?

Der Leistungsprozess beschreibt den Weg von der ersten Kundenanfrage bis zur fertigen Leistung.

Im IT-Bereich kann dieser Prozess zum Beispiel so aussehen:

| Schritt              | Bedeutung                                            |
| -------------------- | ---------------------------------------------------- |
| Anfrage              | Kunde beschreibt ein Problem oder einen Bedarf       |
| Anforderungsaufnahme | Anforderungen werden gesammelt und geklärt           |
| Beratung             | mögliche Lösungen werden erklärt                     |
| Angebot              | Kosten und Leistungen werden schriftlich dargestellt |
| Auftrag              | Kunde entscheidet sich für eine Lösung               |
| Beschaffung          | Hardware, Software oder Lizenzen werden bestellt     |
| Umsetzung            | Installation, Konfiguration und Einrichtung          |
| Test                 | Funktion und Anforderungen werden geprüft            |
| Übergabe             | Lösung wird dem Kunden übergeben                     |
| Support              | Betreuung nach der Übergabe                          |

Kundenanforderungen müssen in jedem Schritt berücksichtigt werden. Wenn Anforderungen am Anfang falsch verstanden werden, kann die gesamte Lösung später unpassend sein.

---

## Kunde ist nicht immer nur eine externe Firma

Ein Kunde kann im IT-Bereich intern oder extern sein.

| Kundenart      | Erklärung                                                                      |
| -------------- | ------------------------------------------------------------------------------ |
| Externer Kunde | eine andere Firma oder Person, die eine IT-Leistung beauftragt                 |
| Interner Kunde | Mitarbeiter oder Abteilungen im eigenen Unternehmen                            |
| Fachabteilung  | Abteilung mit fachlichen Anforderungen, zum Beispiel Buchhaltung oder Vertrieb |
| Endbenutzer    | Person, die später wirklich mit dem System arbeitet                            |
| Entscheider    | Person, die Budget oder Freigabe gibt                                          |

Wichtig ist: Nicht immer ist die Person, die bezahlt, auch die Person, die später mit dem System arbeitet.

Deshalb müssen verschiedene Perspektiven berücksichtigt werden.

---

## Bedarf, Wunsch und Anforderung

Bei Kundengesprächen muss man unterscheiden, ob etwas ein echter Bedarf, ein Wunsch oder eine konkrete Anforderung ist.

| Begriff     | Bedeutung                                                   |
| ----------- | ----------------------------------------------------------- |
| Bedarf      | etwas wird wirklich benötigt, damit die Arbeit funktioniert |
| Wunsch      | etwas wäre angenehm, ist aber nicht zwingend notwendig      |
| Anforderung | konkret beschriebene Bedingung an die Lösung                |

Ein Kunde sagt vielleicht:

> “Der Computer soll schnell sein.”

Das ist noch keine genaue Anforderung.

Besser wäre:

> “Der Computer soll gleichzeitig Office, Browser, Teams und eine Fachsoftware flüssig ausführen können.”

Noch genauer wäre:

> “Der Arbeitsplatz benötigt mindestens 16 GB RAM, eine SSD und zwei Monitoranschlüsse, weil mehrere Programme parallel genutzt werden.”

Je genauer Anforderungen formuliert sind, desto besser kann eine passende Lösung geplant werden.

---

## Arten von Kundenanforderungen

Kundenanforderungen können in verschiedene Bereiche eingeteilt werden.

| Art der Anforderung             | Bedeutung                                                    |
| ------------------------------- | ------------------------------------------------------------ |
| funktionale Anforderungen       | was das System tun soll                                      |
| nicht-funktionale Anforderungen | wie gut oder unter welchen Bedingungen es funktionieren soll |
| technische Anforderungen        | Hardware, Software, Netzwerk, Schnittstellen                 |
| wirtschaftliche Anforderungen   | Budget, Kosten, Nutzen                                       |
| Sicherheitsanforderungen        | Schutz von Daten und Systemen                                |
| rechtliche Anforderungen        | Datenschutz, Lizenzrecht, Vorgaben                           |
| organisatorische Anforderungen  | Arbeitsabläufe, Zuständigkeiten, Support                     |
| ergonomische Anforderungen      | Arbeitsplatzgestaltung und Bedienbarkeit                     |

Diese Einteilung hilft, Anforderungen strukturiert zu erfassen.

---

## Funktionale Anforderungen

Funktionale Anforderungen beschreiben konkrete Funktionen.

Sie beantworten die Frage:

> Was soll das System können?

Beispiele:

- Benutzer sollen sich anmelden können.
- Der Arbeitsplatz soll Zugriff auf Netzlaufwerke haben.
- Der Benutzer soll drucken und scannen können.
- Eine bestimmte Fachsoftware soll installiert sein.
- Der Laptop soll an eine Dockingstation angeschlossen werden können.
- Zwei Monitore sollen gleichzeitig genutzt werden.

Funktionale Anforderungen sind oft direkt prüfbar.

---

## Nicht-funktionale Anforderungen

Nicht-funktionale Anforderungen beschreiben Eigenschaften der Lösung.

Sie beantworten eher die Frage:

> Wie soll das System funktionieren?

Wichtige nicht-funktionale Anforderungen sind:

| Bereich         | Bedeutung                                         |
| --------------- | ------------------------------------------------- |
| Leistung        | System soll schnell genug arbeiten                |
| Zuverlässigkeit | System soll stabil laufen                         |
| Sicherheit      | Daten und Zugänge sollen geschützt sein           |
| Bedienbarkeit   | Benutzer sollen gut damit arbeiten können         |
| Wartbarkeit     | IT soll das System einfach pflegen können         |
| Skalierbarkeit  | Lösung soll später erweiterbar sein               |
| Verfügbarkeit   | System soll möglichst zuverlässig erreichbar sein |

Nicht-funktionale Anforderungen werden oft unterschätzt, sind aber für den späteren Betrieb sehr wichtig.

---

## Technische Anforderungen

Technische Anforderungen beschreiben konkrete technische Eigenschaften.

Dazu gehören zum Beispiel:

- CPU-Leistung
- RAM-Größe
- SSD-Kapazität
- Monitoranzahl
- Netzwerkanschluss
- WLAN-Standard
- Betriebssystem
- Softwareversionen
- Schnittstellen
- Druckerkompatibilität
- Domänenanbindung
- Verschlüsselung
- Backup-Anbindung

Technische Anforderungen sollten nicht isoliert betrachtet werden. Sie ergeben sich aus den Aufgaben des Benutzers und der vorhandenen IT-Umgebung.

---

## Wirtschaftliche Anforderungen

Wirtschaftliche Anforderungen betreffen Kosten, Nutzen und Budget.

Wichtige Fragen:

- Wie hoch ist das Budget?
- Welche Kosten entstehen einmalig?
- Welche Kosten entstehen regelmäßig?
- Gibt es Lizenzkosten?
- Wie lange soll das Gerät genutzt werden?
- Wie hoch sind Wartungs- und Supportkosten?
- Welche Ausfallkosten entstehen bei Problemen?
- Lohnt sich ein teureres Gerät langfristig?

Eine Lösung kann technisch sehr gut sein, aber wirtschaftlich unpassend, wenn sie das Budget sprengt oder unnötig hohe Folgekosten verursacht.

---

## Sicherheitsanforderungen

Sicherheitsanforderungen beschreiben, wie Systeme und Daten geschützt werden müssen.

Wichtige Punkte:

- sichere Anmeldung
- starke Passwörter
- Mehrfaktor-Authentifizierung
- Verschlüsselung
- Benutzerrechte
- Virenschutz oder Endpoint-Security
- Firewall
- sichere Updates
- Schutz vor unbefugtem Zugriff
- Backup
- Zugriff nur auf notwendige Daten

Besonders bei mobilen Geräten, personenbezogenen Daten oder geschäftskritischen Informationen müssen Sicherheitsanforderungen früh berücksichtigt werden.

---

## Rechtliche Anforderungen

IT-Lösungen müssen auch rechtliche Vorgaben beachten.

Dazu gehören zum Beispiel:

- Datenschutz
- Lizenzbedingungen
- Aufbewahrungspflichten
- Arbeitsrecht
- Barrierefreiheit
- branchenspezifische Vorgaben

Im Arbeitsalltag bedeutet das zum Beispiel:

- Software muss korrekt lizenziert sein.
- Personenbezogene Daten müssen geschützt werden.
- Benutzer dürfen nur auf Daten zugreifen, die sie wirklich benötigen.
- Cloud-Dienste müssen datenschutzrechtlich geprüft werden.
- Dokumentation muss nachvollziehbar sein.

---

## Organisatorische Anforderungen

Organisatorische Anforderungen betreffen Arbeitsabläufe und Zuständigkeiten.

Beispiele:

- Wer darf Störungen melden?
- Wer bekommt Administratorrechte?
- Wer genehmigt neue Software?
- Wer verwaltet Benutzerkonten?
- Wie werden Geräte ausgegeben?
- Wie läuft die Rückgabe von Geräten?
- Wer ist für Updates verantwortlich?
- Wie wird Support dokumentiert?

Eine technische Lösung funktioniert nur gut, wenn auch die organisatorischen Abläufe klar sind.

---

## Ergonomische Anforderungen

Ein IT-Arbeitsplatz soll nicht nur technisch funktionieren, sondern auch gesund und gut nutzbar sein.

Wichtige Punkte:

- Monitorhöhe
- Bildschirmgröße
- Tastatur und Maus
- Sitzposition
- Beleuchtung
- Lautstärke
- Kabelmanagement
- Barrierefreiheit
- Bedienbarkeit der Software

Ergonomie ist wichtig, weil Mitarbeiter viele Stunden am Arbeitsplatz verbringen. Schlechte Ergonomie kann zu gesundheitlichen Problemen und geringerer Produktivität führen.

---

## Kundenzufriedenheit

Kundenzufriedenheit entsteht, wenn die gelieferte Lösung die Erwartungen des Kunden erfüllt oder übertrifft.

Dafür müssen drei Dinge zusammenpassen:

| Bereich                 | Bedeutung                                    |
| ----------------------- | -------------------------------------------- |
| technische Qualität     | Lösung funktioniert zuverlässig              |
| wirtschaftlicher Nutzen | Kosten und Nutzen passen zusammen            |
| Servicequalität         | Kommunikation, Support und Übergabe sind gut |

Ein technisch gutes System kann trotzdem schlecht bewertet werden, wenn Kommunikation, Dokumentation oder Übergabe schlecht sind.

Gute Kundenzufriedenheit entsteht durch:

- klare Kommunikation
- realistische Beratung
- saubere Anforderungsaufnahme
- verständliche Angebote
- zuverlässige Umsetzung
- Tests vor Übergabe
- gute Dokumentation
- erreichbaren Support

---

## Anforderungen priorisieren

Nicht alle Anforderungen sind gleich wichtig.

Eine einfache Methode ist die Einteilung in:

| Priorität  | Bedeutung                              |
| ---------- | -------------------------------------- |
| Muss       | zwingend erforderlich                  |
| Soll       | wichtig, aber nicht absolut notwendig  |
| Kann       | optional, wenn Budget oder Zeit reicht |
| Nicht-Ziel | bewusst nicht Teil der Lösung          |

Diese Einteilung hilft, Entscheidungen zu treffen, wenn Budget, Zeit oder technische Möglichkeiten begrenzt sind.

Beispiel:

- Muss: Gerät muss mit der vorhandenen Software funktionieren.
- Soll: Gerät soll zwei Monitore unterstützen.
- Kann: Gerät kann besonders leicht sein.
- Nicht-Ziel: Gaming-Leistung ist nicht erforderlich.

---

## Anforderungen dokumentieren

Anforderungen müssen schriftlich dokumentiert werden.

Das ist wichtig, damit Kunde und IT-Dienstleister das gleiche Verständnis haben.

Dokumentiert werden sollten:

- Ausgangssituation
- Ziel der Lösung
- funktionale Anforderungen
- nicht-funktionale Anforderungen
- technische Anforderungen
- Sicherheitsanforderungen
- Budgetrahmen
- Lieferumfang
- offene Fragen
- Annahmen
- Abgrenzungen
- Akzeptanzkriterien

Ohne Dokumentation entstehen schnell Missverständnisse.

---

## Akzeptanzkriterien

Akzeptanzkriterien beschreiben, wann eine Lösung als erfolgreich umgesetzt gilt.

Sie müssen möglichst klar und prüfbar sein.

Beispiele:

- Der Benutzer kann sich mit seinem Konto anmelden.
- Der Laptop verbindet sich mit dem Firmennetzwerk.
- Zwei Monitore funktionieren über die Dockingstation.
- Der Netzwerkdrucker ist erreichbar.
- Die benötigte Fachsoftware startet ohne Fehler.
- Die Festplattenverschlüsselung ist aktiv.
- Updates wurden installiert.

Akzeptanzkriterien helfen bei Tests und bei der späteren Übergabe.

---

## Kommunikation mit dem Kunden

Gute Kommunikation ist ein zentraler Teil des Leistungsprozesses.

Wichtig ist:

- aktiv zuhören
- Rückfragen stellen
- technische Begriffe einfach erklären
- keine falschen Versprechen machen
- Risiken offen ansprechen
- Entscheidungen dokumentieren
- Änderungen schriftlich festhalten

Viele Probleme entstehen nicht durch Technik, sondern durch unklare Kommunikation.

Ein Kunde sagt oft nicht direkt die technische Lösung, sondern beschreibt ein Problem. Die Aufgabe der IT ist es, daraus die passende technische Lösung abzuleiten.

---

## Änderungen im Projekt

Anforderungen können sich während eines Projekts ändern.

Das ist normal, muss aber kontrolliert werden.

Änderungen können Auswirkungen haben auf:

- Kosten
- Zeitplan
- Hardwareauswahl
- Softwareauswahl
- Sicherheit
- Support
- Dokumentation

Deshalb sollten Änderungen nicht einfach nebenbei umgesetzt werden. Sie müssen geprüft, dokumentiert und freigegeben werden.

Das nennt man Änderungsmanagement oder Change Management.

---

## Marketing und Verkaufsförderung im IT-Bereich

Marketing und Verkaufsförderung bedeuten im IT-Bereich nicht nur Werbung.

Es geht auch darum, Leistungen verständlich darzustellen und Kunden von einer passenden Lösung zu überzeugen.

Wichtige Punkte:

- Vorteile einer Lösung erklären
- Nutzen für den Kunden zeigen
- technische Informationen verständlich machen
- Vergleich zwischen Lösungen darstellen
- Qualität und Service hervorheben
- Vertrauen durch gute Beratung schaffen

Für FISI ist wichtig, technische Lösungen so zu erklären, dass Kunden sie verstehen und eine fundierte Entscheidung treffen können.

---

## Auftragsbearbeitung

Auftragsbearbeitung bedeutet, dass ein Kundenauftrag geplant, durchgeführt und dokumentiert wird.

Typische Schritte:

1. Anfrage prüfen
2. Anforderungen aufnehmen
3. Lösungsvorschlag erstellen
4. Angebot vorbereiten
5. Auftrag bestätigen
6. Material beschaffen
7. Umsetzung planen
8. Installation durchführen
9. Funktion testen
10. Übergabe dokumentieren
11. Supportphase starten

Eine strukturierte Auftragsbearbeitung verhindert Chaos und sorgt dafür, dass nichts Wichtiges vergessen wird.

---

## Projektmanagement-Bezug

Größere IT-Aufträge werden oft als Projekt durchgeführt.

Ein Projekt hat meistens:

- ein klares Ziel
- einen Anfang und ein Ende
- begrenzte Zeit
- begrenztes Budget
- bestimmte Anforderungen
- mehrere Beteiligte
- Risiken
- Dokumentationspflicht

Auch kleine Arbeitsplatzprojekte profitieren von einfachem Projektdenken.

Dazu gehören Planung, Aufgabenverteilung, Zeitplanung, Risikoabschätzung und Kontrolle der Ergebnisse.

---

## Praxisbeispiele

### Beispiel 1: Büroarbeitsplatz

Ein Mitarbeiter in der Verwaltung braucht einen stabilen Arbeitsplatz für E-Mail, Office, Browser, Drucker und interne Anwendungen. Wichtige Anforderungen sind Zuverlässigkeit, ausreichender RAM, SSD, Druckerzugriff, Benutzerkonto und Sicherheitssoftware.

### Beispiel 2: Homeoffice-Arbeitsplatz

Ein Mitarbeiter arbeitet regelmäßig von zu Hause. Wichtig sind Laptop, VPN oder sicherer Cloud-Zugriff, Webcam, Headset, Mehrfaktor-Authentifizierung, Verschlüsselung und klare Supportwege.

### Beispiel 3: Entwicklerarbeitsplatz

Ein Entwickler benötigt mehr Leistung, weil Entwicklungsumgebung, Git, Docker, virtuelle Maschinen und mehrere Programme gleichzeitig genutzt werden. Wichtig sind starke CPU, viel RAM, schnelle SSD und passende Rechte für Entwicklungswerkzeuge.

---

## Typische Fehler

| Fehler                             | Problem                                          |
| ---------------------------------- | ------------------------------------------------ |
| Anforderungen nur mündlich klären  | Missverständnisse sind später schwer nachweisbar |
| Kundenwünsche nicht hinterfragen   | falsche oder überteuerte Lösung möglich          |
| nur technische Daten betrachten    | Arbeitsabläufe und Benutzer werden vergessen     |
| Sicherheit zu spät beachten        | spätere Nachbesserung wird aufwendig             |
| Budget ignorieren                  | Lösung ist nicht wirtschaftlich                  |
| Änderungen nicht dokumentieren     | Projekt wird unübersichtlich                     |
| keine Akzeptanzkriterien festlegen | Übergabe und Prüfung werden schwierig            |

---

## FISI-Bezug

Für Fachinformatiker für Systemintegration ist die Arbeit mit Kundenanforderungen eine zentrale Fähigkeit.

Ein FISI muss technische Anforderungen verstehen, aber auch mit Menschen kommunizieren können. Es reicht nicht, Hardware und Software zu kennen. Man muss erkennen, welches Problem gelöst werden soll und welche Lösung im konkreten Umfeld sinnvoll ist.

Dabei verbindet man Technik, Organisation, Wirtschaftlichkeit, Sicherheit und Dokumentation.

Ein guter FISI fragt nicht nur:

> Welche Hardware soll gekauft werden?

sondern:

> Welche Aufgabe soll mit dieser IT-Lösung zuverlässig, sicher und wirtschaftlich unterstützt werden?

---

## Kurze Zusammenfassung

Kundenanforderungen sind die Grundlage für eine passende IT-Lösung.

Sie beschreiben, was ein System leisten soll, welche technischen und organisatorischen Bedingungen gelten und welche Erwartungen der Kunde hat.

Wichtige Anforderungsarten sind funktionale, nicht-funktionale, technische, wirtschaftliche, sicherheitsrelevante, rechtliche, organisatorische und ergonomische Anforderungen.

Für FISI ist wichtig, Anforderungen sauber aufzunehmen, zu priorisieren, zu dokumentieren und daraus eine passende Lösung abzuleiten.
